# Which console surface each screen drawing depicts.
#
# The gallery tests next door all check screens against the README: that a
# referenced screen exists, that an existing screen is shown, that the
# numbering has no gap. Every one of them starts from the screens. None asks
# whether a *surface* has a screen at all — so a feature can ship with nothing
# drawn and no test says a word. That has now happened three times: voice
# cloning, the recoverable watermark and the chat role went two whole versions
# undrawn, and the error-reporting card and its first-run notice went out in
# 0.19.0 the same way.
#
# This file is the missing direction. Every component under app/src/screens/
# and every top-level surface component must appear here, so a new one fails
# the suite until somebody decides what it looks like.
#
#   <component>   <screens>   one or more numbers, comma-separated
#   <component>   undrawn     acknowledged as having no drawing
#   <component>   unaudited   seeded, never verified — see below
#
# `undrawn` is a ratchet: the count may fall and must never rise. Adding a
# surface without a drawing therefore fails, which is the whole point.
#

# **0.40.9 audited five of the seven; 0.42.3 closed the last two.** The five
# were resolved by reading the component's own heading and matching it to a
# screen title, rather than by matching its name — which is what left them
# unresolved in the first place: `Campaigns` draws "Where the Money Goes",
# `Org` draws "The Ecosystem", `Simulate` draws "What Would They Do". None of
# those three share a word with the component that renders them.
#
# `Discover` and `Wall` were the suspicion this file recorded, confirmed: no
# screen in the gallery carried either heading under any name, because neither
# had ever been drawn. Both surfaces shipped in the community round and were
# iterated on for thirty versions with nothing in the gallery — `undrawn=0`
# was false for exactly as long as `unaudited` was covering for it, and
# `unaudited` was the softer word of the two. 185 and 186 are the drawings.
#
#     asked     is every component accounted for in this file
#     mattered  does every component have a drawing
#
# ceiling: undrawn=0 unaudited=0
#
# `unaudited` was the honest seed. These components predated the file and
# their screens were not confirmed one by one — matching a component name
# against a screen title resolved only ten of twenty-four, because titles are
# written for the person using the app ("How Should They Work?") and component
# names are written for the person editing it ("Delegate"). Guessing the rest
# would have produced a mapping that looked complete and was not. The column
# is now empty, its ceiling is zero, and it is not a status a new component
# may use — from here every surface either has a drawing or fails the suite.
