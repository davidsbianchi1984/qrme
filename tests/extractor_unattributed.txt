# Path-shaped literals that no call form encloses, and are not requests.
# Checked by test_the_extractor_knows_every_call_shape.py, ratcheted in both
# directions: a new one has to be justified here, and one that has gone has to
# be struck.
#
# A literal in this file is a claim that the surface writes this path and does
# not send it. That claim is the only thing standing between the route audit
# and a blind spot, so each line carries the reason it is here rather than a
# shape for the extractor to learn.

# `defaultBase()` asks whether `window.location.pathname` starts with this —
# a question about where the page is being served from, not a call. Documented
# in clientpaths.paths() since long before this check existed.
console: app/src/api.ts  /app

# Not a path at all. It is the regular expression that trims trailing slashes
# off the problem-collector URL, and it is in this file only because it begins
# with a slash and survives the URL-safe test.
ios: native/ios/Sources/Problems.swift  /+$

# Two URL *builders*: each returns an absolute address for something else to
# open. `DeskViewUrl` hands its result to an image view, and the ceremony URL
# is opened in the reader's browser so the signing happens on a page this app
# does not draw. The audit asks what this client sends, and neither of these
# is sent by it.
windows: native/windows/ApiClient.cs  /desks/{deskId}/view.webp
windows: native/windows/ApiClient.cs  /signatures/ceremony?{query}

# The redeem field on the export card accepts a pasted handoff URL and asks
# whether it contains this fragment before parsing the profile id and ticket
# out of it. A question about a string somebody pasted, not a request — the
# actual request is the `req()` call two lines down, which the audit reads.
console: app/src/screens/Identity.tsx  /export/handoff/
