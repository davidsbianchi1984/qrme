# ## 0.47.9 — what these rows actually are
#
# For three releases this file called itself a **backlog** and implied the work
# was deletion. That was wrong, and the number was hiding something worse than
# waste.
#
# **263 of the 335 rows here are asked for by a different shell.** They are not
# rows nobody uses; they are rows *this* shell does not use and a sibling does.
# Every one of them is the same question: this screen exists on all three
# shells, so why does one of them say less?
#
#     asked     is this row used anywhere
#     mattered  does this shell say what its siblings say
#
# Only 72 rows are asked for by no shell at all. Those are the deletion
# candidates. The rest are a to-do list about screens.
#
# ### What that mislabelling was hiding
#
# The voiceprint consent block. Every shell shows a heading — *what this
# permission holds* — and beneath it three sentences: the watermark, the
# attestation, the withdrawal. Android and the desktop took all three from the
# table. **The iPhone had them hardcoded in English**, in an array handed to a
# `ForEach`, which is not the start of a `Text(` and so was read by nothing.
# The screen showed a translated promise and then said, in one language only,
# the three things the promise consists of.
#
# It also prepended `"· "` to each line. Android's copy of the same block
# carries a note saying the bullet belongs *in* the row so an RTL reader gets
# it on the correct side. That note had been there since it was written.
#
# ### Still open, and named rather than counted
#
# **The iPhone's beacon scanner has no camera-permission state.** Android shows
# *Camera access is needed to read a beacon* and *Nothing is recorded — frames
# are read and discarded*; iOS guards on `AVCaptureDevice.default(for: .video)`
# and, when permission is refused, renders nothing at all. That is a missing
# screen state rather than a missing string, so the rows stay recorded here
# until the state exists — the second of those sentences is a privacy promise
# the Android reader is given and the iPhone reader is not.
#
# The two-direction ratchet is JIM's: `ceiling` is a maximum over the three
# shells, so the count could rise on one shell while the check passed, if the
# total were not also held.
#
# ### 0.54.0 — two of the named ones closed
#
# **The iPhone's camera-permission state now exists.** `configure()` used to
# hit `AVCaptureDevice.default(for: .video)`, fail, and return — leaving a
# black `CameraPreview` with "point at a beacon" floating over it. A person
# who declined got a dead screen and no reason. `nbcn.camera` and
# `nbcn.nothing` were in this shell's own table, translated ten ways, asked
# for by nothing. The second is the one that mattered: *"Nothing is recorded —
# frames are read and discarded"* is a promise about what this app does with a
# camera, and only Android readers were being given it.
#
# **Windows was printing "scan(s)" and "picked up" in English.**
# `ReachPage.ReloadBeacons` built its detail line with string literals while
# `nmg.beacon.scans` and `nmg.beacon.pickedup` sat translated beside it. An
# owner reading the app in German saw "Garten · 3 scan(s) · picked up" —
# translated chrome around the two words carrying the meaning. Exactly the
# shape 0.47.9 found in the iPhone's voiceprint consent block, in a different
# shell.
#
# **And three more of the same, found by turning that into a guard.**
# `test_a_shell_does_not_print_what_it_translated.py` extracts every string
# literal from every screen and compares it against that shell's own table:
# Windows typed out *"Enter a display name and a persona to continue."* and
# *"No profile here produced this text."*, Android typed out *"Steering
# applied — it rides on every reply."* Twenty-four more are recorded there,
# and sorting them is real work rather than a sweep — a label is read, a value
# is posted back to a route that compares against English, and translating one
# of those turns a working form into a 422.
#
# ### 0.54.1 — the twenty-four read, one at a time
#
# The guard added in 0.54.0 recorded twenty-four literals a shell shows that
# its own table already translates, and said sorting them was the work. It
# was. **Twelve were labels and are now keys**; the other twelve are values
# this shell posts back to a route that compares against English, and
# translating one turns a working form into a 422.
#
# The labels: the steering group headings (`Behavior`, `Intimacy (18+)`) on
# Android and Windows, the tier names (`Friendly`, `Rated 18+`) and
# `Lifetime` on Android, the packs `Download` button on both phones, and the
# signature attestation — *"I attest this is accurate and complete"* — which
# is free text the server stores as given, so somebody signs in the words
# they would use rather than the ones this app happens to be written in.
#
# **And a split the sort exposed.** `nmg.pack.robot` ("🤖 ROBOT") and
# `nmg.pack.robot.tasks` ("🤖 ROBOT TASKS") were both held by all three
# shells for the same badge on the same kind of pack, with iOS using one and
# Windows the other. One badge, one word, one key: all three now use
# `.tasks`, and the short row is deleted from all three tables rather than
# left translated ten ways for nobody.
#
