# English strings on the screens behind a translated tab bar, per shell.
# Checked by test_the_tabs_are_translated_and_the_screens_are_not.py, and
# ratcheted in both directions: the count may not rise, and the record may not
# sit more than 20 above the real number.
#
# This is a measurement, not a claim. The console guard in the QRME repo
# (test_the_nav_is_translated_and_nothing_behind_it_is.py) found forty-six
# translated sidebar labels in front of 1577 English screens and made the same
# choice: record it honestly rather than pretend.
#
#     asked     is the chrome localized
#     mattered  is anything behind the chrome localized
#
# These are the worst three of the nine. This product's shells localize their
# tab bars and almost nothing else — the Windows shell answered in the reader's
# language exactly twice, in the nav loop and on one button, before this round
# measured it.
#
# The sibling product carved its alarm surface out of these numbers this round,
# by name rather than by count, because a count cannot tell you *which* string
# a person could not read. Nothing has been carved out here yet. The obvious
# candidate is the objection and audit surface — the screens where somebody
# contests what a synthetic profile said about them — for the same reason:
# those are decisions, not descriptions.
#
# The Windows count is the largest because that shell puts its wording in XAML
# attributes, which cannot be re-read when the language changes. Localizing a
# Windows string means moving it to the code-behind first.

# **Corrected in 0.30.9.** The numbers first recorded here counted any string
# literal containing a letter, which counted format fragments like
# `"\(dim): \(n)%"` — whose only letters are variable names nobody reads — as
# English prose. Roughly seventy-five of them across the nine shells.
#
#     asked     does this literal contain letters
#     mattered  does this literal contain words a reader reads
#
# The ratchet caught it by firing on a card that had just been fully
# localized, which is a measurement saying the opposite of the truth. The
# counts below are what is actually unreadable.

# 0.40.6 lowered all three: the accountless screen — the one built for a
# person who has no profile and therefore no profile language — now reads its
# strings from each shell's table. Windows fell furthest per screen because
# every one of its sentences was a XAML attribute, which is written once at
# parse time and cannot be re-read in another language; localizing them meant
# moving them to the code-behind first.
# 0.46.8 lowered all three by finishing the console that runs a profile's
# public reach. It is one surface under three names — `ManageView` on iOS,
# `ReachPage` on Windows, loose panels in `Screens.kt` on Android — and its
# own sub-tabs (Summon, Market, Packs, License, Earn) were English on every
# shell, which is this arc's opening finding one level down.
#
# The line worth naming: the wellbeing card told readers in ten languages to
# "call or text 988" — a US number that reaches nothing from Spain, Japan,
# India or Egypt. The sibling product settled this wording rounds ago. It now
# says: contact your local crisis line or emergency services.

# 0.46.9 took the six screens that exist on all three shells at once —
# Overview, Compose, Posts, Connect, Robots and Study — rather than one shell
# at a time, because working them one at a time is what produced the split
# wordings this arc keeps finding.
#
# The sharpest thing it found is not in these numbers. The Windows shell's
# Sign out button lives in NavigationView.PaneFooter, and LocalizeNav() walks
# Nav.MenuItems — so it never reached it. The button that ends a session read
# "Sign out" in every language, while the row it needed, `action.sign_out`,
# had been in the iOS and Android tables since they were written. Android was
# using it. iOS had it and hardcoded the English anyway. One control, three
# states of done.
